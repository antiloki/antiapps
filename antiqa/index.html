QA anything. Through hell and back.

An end-to-end tester for any app: a web page, a terminal program, a desktop window. It plays your user stories, keeps video evidence when something misses, and writes a bug report a coding agent can pick up.

How it works

Three steps. No new account.

01

Point it at your app

antiqa scan reads a web page, a Tauri, GTK or Qt window, a terminal program or a browser extension, and antiqa onboard drafts a pack: the study and the stories, written by code from what the scan found. A local model may propose more, and every proposal must cite the app map or it is rejected.

02

Play the stories

Each story is played in a real browser, a terminal or a window. The verdict is computed in code from what the screen showed, never by a model. Every miss gets a video, a replay and a trace.

03

Get a report an agent can fix

Every failure is triaged, then written to BUG-REPORT.md with an evidence.zip, and antiqa mcp lets an agent start runs and read the results itself. Exit codes tell your pipeline what happened.

What's next

Many new things since 0.0.43.

These are built and tested on the development branch. They are not in the 0.0.43 download below; they ship with the next release.

ROUTINES

Stories that run on their own

Put a story on a schedule from the story itself. One scheduler for all of them runs one job at a time, and only when memory and video memory have room. Missed runs follow a policy you choose, and a systemd timer keeps them going with the window closed.

QUALITY X-RAY

The health of the product, counted

From the history of your runs: what keeps coming back after a fix, where issues pile up, which tests flip, how long fixes take. All code, no model, and no source code read.

ISSUES

Issues like GitHub's

A replay command, the environment, a marked picture with circles and arrows drawn by code, the console and network around the failure, and the common causes and fixes. Send it to GitHub and keep it in step.

ERROR LIBRARY

439 shapes of error

Every error fits a shape by code, with what is common for that kind. The library grows: a local model drafts a candidate for a new kind, code vets it, and you decide.

RECORD

Use the app once, keep it as a story

Click through a web page or a Tauri window and every step is saved as a story as you go, shown live inside the antiQA window. File pickers are answered from a test-files folder, so an upload replays the same way every time.

LOOK

A small vision model, only if it qualified

A local model (LFM3 first, Qwen3 as the fallback) answers one yes/no question about a screenshot. It counts only after it passes a benchmark, and a miss becomes a defect only when you confirm it.

What runs today

Honest about where it is.

  • Gated pipeline: study, stories, harness, run, triage, report
  • Exit 0 no defect, 1 defect, 2 a gate failed
  • scan, onboard, drift, heal and grow: discover an app, draft its stories, notice when they go stale, mend a rename
  • An MCP server (antiqa mcp) and a JSON result for agents
  • The antiQA window, and antiqa family to test a whole set of projects
  • Local models only when they pass a check, and never for a verdict
  • 0.0.43 is a Linux x86_64 build. macOS and Windows were not built.
